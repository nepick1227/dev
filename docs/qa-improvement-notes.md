# QA 개선 항목 로그

QA 진행 중 발견했으나 즉시 반영하지 않고 별도 결정이 필요한 항목을 모읍니다.
각 항목은 관련 시트/케이스, 현재 동작, 제안, 결정 상태를 기록합니다.

---

## [01·02] 로그인 실패의 도착지가 두 갈래로 갈림 (흐름 재설계)

- **관련**: 01 로그인 3-1~3-4 / 02 약관·회원가입 4-2 / `/auth/error`
- **현재 동작**: 로그인/인증 실패가 두 화면으로 나뉘어 처리됨
  - 갈래 1 — `/auth/login?error=...` 인라인 문구: 코드 교환 실패, 탈퇴 30일 이내, 네이버 provider 충돌
  - 갈래 2 — `/auth/error` 전용 페이지: 소셜 동의 취소, 네이버 CSRF/토큰 예외, 가입 중 뒤로가기
- **문제점**:
  1. 사용자가 스스로 "취소"한 것이 "일시적인 오류가 발생했어요" 전체 화면으로 이어져 어색함
  2. 유사한 실패(코드 교환 실패 vs 네이버 토큰 실패)가 서로 다른 화면으로 가서 경험이 불일치
- **제안 방향**:
  - 소셜 취소 → 로그인 화면으로 조용히 복귀 (문구 없음 또는 가벼운 안내)
  - 일회성 실패(토큰/검증) → 로그인 화면 인라인 "로그인에 실패했습니다"
  - 반복 실패·복구 불가 상황만 `/auth/error`(문의하기)로 유지
- **결정**: 보류 — 가입 퍼널 흐름 재설계 범위. 02 시트 마무리 후 별도 결정 예정

## [02] 환경/DB 확인 필요 (코드 아님 — 수기 확인)

QA에서 NG(✕)로 잡혔으나 코드는 정상. 운영/개발 DB의 migration 적용 여부 또는 테스트 방법 문제로 판단됨.

### 닉네임 중복 확인 3종 미동작 (5-4 사용가능 / 5-5 사용중 / 5-6 확인실패)

- **증상**: 세 케이스 모두 NG. 셀 노트 "동일한 닉네임 있으나 중복 체크 동작 안함"
- **코드 상태**: `app/auth/signup/page.tsx`의 `checkNickname`은 정상. `is_active_nickname_available` RPC 결과만 처리
- **원인 후보**:
  1. migration `20260628005000_private_profile_select.sql`(RPC 정의)가 테스트 환경에 **미적용** → 함수 없으면 항상 "확인 실패"
  2. `/auth/signup`에 **세션 없이 직접 접근**해 테스트 → 함수 내 `auth.uid() IS NULL`이면 예외 → 항상 실패
- **확인 방법**: 정상 로그인 흐름(소셜 인증 → 신규 유저)으로 진입했는지 + 해당 환경에 위 migration 적용됐는지
- **결정**: 수기 확인 대기 (DEV/PROD migration 동기화 점검)

### 나중에 입력할게요 - 기본 닉네임 중복 미차단 (7-5)

- **증상**: NG. 셀 노트 "소셜 계정 닉네임으로 자동 생성되나 중복을 잡지는 못함"
- **코드 상태**: `handleSkip`은 upsert 후 `23505`(unique 위반)를 캐치함 — 코드는 정상
- **원인 후보**: 활성 계정 닉네임 unique 제약 migration `20260628002000_unique_active_nickname.sql` 미적용 시 중복이 그냥 통과
- **결정**: 수기 확인 대기 (위와 동일한 migration 동기화 점검)

### 위치 권한 미허용 → 허용 시 화면 새로고침 안 됨 (셀 노트 G20)

- **증상**: 브라우저 위치 권한을 미허용 상태에서 허용으로 바꿔도 화면(지도 등)이 자동 반영되지 않음
- **성격**: 브라우저 권한 상태 변화 감지(Permissions API) 미구현으로 추정 — 03 홈(지도) 시트와 함께 볼 항목
- **결정**: 03 시트에서 재현·판단

## [02] 결정 필요한 개선 코멘트 (정의서 💡 + 셀 노트)

- **4-2 뒤로가기 → /auth/error**: 가입 중 뒤로가기가 에러 화면으로. → "그만두시겠어요?" confirm 모달이 자연스러움 (위 [01·02] 흐름 재설계와 연동)
- **3-3 권한 팝업 2연속**: 약관 동의 직후 위치+알림 팝업 연속 노출은 거부율 높음 → 위치는 홈 지도 최초 진입 시, 알림은 첫 기록 저장 후로 지연 요청

- **6-2 성별 UI/라벨 불일치**: 가입=세로 라디오 카드 / 프로필 편집=가로 3버튼, 라벨도 "답변하지 않음" vs "선택 안 함" → 컴포넌트·라벨 통일 (08 프로필 편집 시트에서 함께 결정)
- **5-4 닉네임 필드 완성도 통일**: 가입 화면 닉네임 입력(상태 아이콘+성공 보더+카운터)이 프로필 편집보다 완성도 높음 → 프로필 편집을 이 사양으로 통일 (08 시트)
- **G16 약관 전문 › 버튼 터치 영역 확장**: 현재 `›` 아이콘 자체만 터치 영역 → 상하 패딩/히트박스 확대 (소규모 코드 수정, 08 통일 작업과 함께 또는 별도)
- **프로필 편집 이탈 가드 부재 (모바일·데스크탑 공통)**: 기록 작성/수정과 달리 프로필 편집은 모바일(`/profile/edit`)·데스크탑(`ProfileEditPanel`) **양쪽 모두 이탈 확인 모달이 없음**(둘 다 "뒤로" 즉시 이동). divergence가 아니라 "둘 다 없음"이므로 섣불리 한쪽에 추가하지 않음. 프로필 편집에도 이탈 가드가 필요한지 **08 시트에서 결정** → 필요하면 ProfileEditForm에 `onHasChanges` 콜백 추가 후 모바일 페이지 + 데스크탑 패널 양쪽에 동일 적용.
